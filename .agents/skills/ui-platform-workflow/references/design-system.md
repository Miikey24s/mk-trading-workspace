# Exploration and shared-system changes

Read only for explicit new direction, Stitch/Figma work, token/component-system
changes, scaling or consumer migration.

- Exploration: confirm current scope/approval authority. Existing Naqex Trader
  direction and retired prototypes are not reopened by a historical prompt.
  Compare meaningful candidates using clarity, density, hierarchy, domain
  ergonomics, accessibility and maintainability; preserve alternatives for review.
- Convergence: use representative screens and interaction states, not one polished
  mockup. Explain design terms plainly when user choice matters. Follow the
  project's recorded agent/user approval authority.
- Systemization: distinguish primitive tokens, semantic roles, components and
  patterns. Keep canonical semantics outside vendor canvases. Generated
  `DESIGN.md` is an agent view of accepted rules, not a second authority.
- Scaling: batch generation only after representative contracts work. Generated
  code must fit the real stack and pass product checks; do not add a framework
  because a generator prefers it.
- Migration: consumers pin versions. Upgrade one bounded consumer/slice, check
  state/visual/interaction compatibility and preserve rollback before propagating.
  Shared promotion requires actual reuse and the relevant release authority.

UI evidence does not grant broker/provider/OAuth, external publication or paid
service authority. Return evidence to the existing plan/task owner.
